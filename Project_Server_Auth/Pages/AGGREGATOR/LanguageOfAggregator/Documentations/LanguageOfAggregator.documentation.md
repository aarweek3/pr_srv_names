# Документация компонента LanguageOfAggregator

Компонент `LanguageOfAggregator` предназначен для управления справочником языков в рамках модуля **Aggregator**. Он обеспечивает локализацию контента (программ, категорий, тегов) и изолирован от системных настроек интерфейса приложения (`LanguageApp`).

## 1. Архитектура

Компонент реализован согласно стандарту **v3.5** (автономность, полный аудит, использование `DateTimeOffset`).

### Стек:
- **DAL**: Entity Framework Core, Repository Pattern.
- **BLL**: Service Pattern, AutoMapper, FluentValidation.
- **API**: ASP.NET Core Web API, Rate Limiting.

## 2. Модели данных

### Сущность (DAL)
`LanguageOfAggregator` (таблица `languages_of_aggregator`):
- `Code` (string, 10): Полный код (например, "ru-RU").
- `ShortCode` (string, 10): Краткий код (например, "ru").
- `Title` (string, 100): Название на английском.
- `NativeTitle` (string, 100): Родное название.
- `IsRtl` (bool): Флаг письма справа налево.
- `Enabled` (bool): Флаг активности.
- `IsDefault` (bool): Флаг основного языка системы.
- `IsSystem` (bool): Флаг защищенного системного языка.
- `IconKey` (string, 20): Ключ иконки или флага.

### DTO (Data Transfer Objects)
- `LanguageOfAggregatorDto`: Полный объект для отображения.
- `CreateLanguageOfAggregatorDto`: Модель для создания.
- `UpdateLanguageOfAggregatorDto`: Модель для частичного обновления.

## 3. Бизнес-логика (Service Layer)

Сервис `LanguageOfAggregatorService` реализует следующие критические правила:

- **Принцип единства Default**: При установке флага `IsDefault` для одного языка, он автоматически снимается со всех остальных.
- **Защита System**: Системные языки (`IsSystem: true`) защищены от удаления и деактивации.
- **Защита Default**: Язык, установленный по умолчанию, нельзя удалить или деактивировать.
- **Уникальность**: Проверка уникальности `Code` и `ShortCode` перед сохранением.

### Инициализация (Seed)
Метод `InitializeAsync` выполняет первоначальное наполнение базы данных из JSON-файла:
1. Ищет `default-aggregator-languages.json` в `wwwroot/data/`.
2. Если файл отсутствует, использует общий `default-languages.json`.
3. Просто сохраняет `IconKey`, который затем используется фронтендом для динамической загрузки через `IconsController`.

## 4. API Эндпоинты

Базовый путь: `api/v1/aggregator/languages`

| Метод | Путь | Описание |
| :--- | :--- | :--- |
| GET | `/` | Получить все языки (параметр `includeDisabled`). |
| GET | `/available` | Получить только активные языки. |
| GET | `/{id}` | Получить язык по ID. |
| POST | `/` | Создать новый язык. |
| PUT | `/{id}` | Обновить данные языка. |
| DELETE| `/{id}` | Удалить язык (кроме системных/дефолтных). |
| POST | `/{id}/default` | Сделать язык основным. |
| PATCH | `/{id}/status` | Включить/выключить язык. |
| POST | `/initialize` | Запустить сид данных из JSON. |
| DELETE| `/hard-reset` | Полная очистка таблицы (TRUNCATE). |

## 5. Валидация

Используется `FluentValidation` со строгими правилами:
- `Code`: Обязателен, макс. 10 символов.
- `Title`/`NativeTitle`: Обязательны, макс. 100 символов.
- `SortOrder`: Не может быть отрицательным.
- `IconKey`: Ограничен 20 символами (соответствие стандарту Icons).

## 6. Связь с LanguageApp

Для подсистемы агрегатора мы используем **тот же механизм загрузки иконок**, что и в основном модуле `LanguageApp`:
1. В базе хранится только **ключ** (`IconKey`), например `flag_ru`.
2. Фронтенд использует компонент `<av-icon [type]="lang.iconKey">`.
3. Контент SVG запрашивается динамически через `api/Icons/content/{key}` или берется из кэша фронтенда.
4. Это обеспечивает единообразие и высокую скорость работы интерфейса.
