# Загрузка иконок в компоненте LanguageApp

Данный документ описывает механизм загрузки и отображения иконок (флагов) для языков приложения на стороне сервера и фронтенда.

## Общая архитектура

Система использует **ключевой подход** (Key-based approach): в базе данных для каждого языка хранится строковый ключ иконки (например, `flag_ru`), а само SVG-содержимое загружается динамически через специализированный сервис иконок.

---

## 1. Серверная часть (Backend - ASP.NET Core)

### Хранение данных
*   **Сущность `LanguageApp`**: Содержит поле `IconKey` (string, max 20). Это имя иконки в системе.
*   **Хранилище иконок**: Все иконки хранятся в таблице `Icons` базы данных (поле `SvgContent`). Каждая запись имеет уникальное имя (поле `Name`), которое соответствует `IconKey`.

### API Эндпоинты
За передачу контента иконок отвечает `IconsController`:
*   `GET /api/Icons/content/{name}` — возвращает SVG-контент одной иконки.
*   `POST /api/Icons/batch-content` — пакетная загрузка нескольких иконок (принимает список имен в теле запроса).

### Инициализация
При первичной инициализации системы (метод `InitializeAsync` в `LanguageAppService`), дефолтные языки загружаются из файла `wwwroot/data/default-languages.json`, в котором уже прописаны базовые `IconKey` (например, `flag_us`, `flag_ru`).

---

## 2. Клиентская часть (Frontend - Angular)

### Модели данных
В Angular-приложении (например, `pr_aurora_admin`) модель языка содержит поле `iconPath` или `iconKey`, которое мапится с бэкенда.

### Компонент отображения (`av-icon`)
Для отображения иконок используется универсальный компонент `IconComponent` (селектор `av-icon`):
```html
<av-icon [type]="data.iconKey || 'default'" [size]="24"></av-icon>
```

**Логика компонента:**
1.  Принимает тип (ключ) иконки.
2.  Обращается к фронтенд-сервису `IconGetService` за контентом.
3.  Выполняет постобработку SVG:
    *   Удаляет XML-декларации.
    *   Гарантирует наличие `viewBox`.
    *   Для монохромных иконок устанавливает `fill="currentColor"`.
    *   Детектирует флаги и многоцветные иконки для отключения принудительной перекраски.

### Сервис загрузки (`IconGetService`)
Обеспечивает эффективную доставку иконок:
1.  **Кэширование**: Использует `Map` для хранения уже загруженных SVG (в памяти).
2.  **Хардкод**: Содержит критически важные иконки (включая некоторые флаги) в `HARDCODED_FLAGS` для мгновенного отображения без сетевого запроса.
3.  **Сетевые запросы**: Если иконки нет в кэше, делает запрос к `api/Icons/content/{name}`.

---

## Процесс загрузки (Step-by-Step)

1.  **Загрузка списка**: Фронтенд вызывает API языков и получает массив объектов с `IconKey`.
2.  **Рендеринг**: Angular перебирает массив и для каждого элемента отрисовывает `<av-icon [type]="lang.iconKey">`.
3.  **Запрос контента**:
    *   `IconComponent` спрашивает у `IconGetService`: "Есть ли у тебя SVG для `flag_ru`?".
    *   Если есть в кэше — возвращает сразу.
    *   Если нет — отправляет HTTP-запрос на сервер.
4.  **Ответ сервера**: `IconsController` находит запись в БД и отправляет строку SVG.
5.  **Отображение**: Фронтенд сохраняет SVG в кэш и вставляет его в DOM через `[innerHTML]`.
