# 📝 Техническое задание: Интеллектуальная система мониторинга и оповещения (Aurora Control)

## 1. Концепция
Система мониторинга должна эволюционировать из пассивного инструмента отображения данных в активную систему контроля здоровья (Health Check), способную самостоятельно оповещать администраторов о проблемах и адаптировать свою работу под нагрузку.

## 2. Глобальная конфигурация (Backend JSON)
Для гибкого управления без пересборки проекта использовать файл `health-policy.json`.

### Структура конфига:
```json
{
  "Thresholds": {
    "PostgreSQL": 150,
    "IdentityAPI": 200,
    "ExternalServices": 1000,
    "Default": 500
  },
  "Alerting": {
    "SmsEnabled": true,
    "Recipients": ["+79000000000"],
    "SilencePeriodMinutes": 30,
    "MinSeverity": "Critical"
  },
  "Monitoring": {
    "ScanIntervalSeconds": 30,
    "BackoffStepsSeconds": [30, 60, 300, 900]
  }
}
```

## 3. Фоновый мониторинг (BackgroundService)
*   **Реализация:** ASP.NET Core `BackgroundService` (Worker).
*   **Логика:**
    1.  Чтение `health-policy.json` при старте.
    2.  Циклический опрос систем на бэкенде каждые `ScanIntervalSeconds`.
    3.  Сравнение реального времени отклика с порогами (`Thresholds`).
    4.  При превышении порогов более чем N раз подряд — инициация алерта.

## 4. Система оповещения (SMS Alerting)
*   **Интерфейс:** `ISmsService` для абстракции провайдера.
*   **Борьба со спамом:** Реализация механизма `SilencePeriod`. Если SMS уже отправлена, следующая отправка блокируется на 30 минут (или иное значение из конфига), если проблема сохраняется.
*   **Типы уведомлений:**
    *   `Down`: Система полностью недоступна.
    *   `Degraded`: Высокая задержка API.

## 5. Адаптивная политика опроса (Frontend Retry Policy)
*   **Механизм:** "Умный интервал".
*   **Логика замедления:** Если сервер вернул статус `Unhealthy`, фронтенд увеличивает время ожидания согласно `BackoffStepsSeconds` (30с -> 1м -> 5м).
*   **Авто-сброс:** Как только приходит первый `Healthy` ответ, интервал немедленно сбрасывается на стандартные 30 секунд.
*   **Принудительный опрос:** Кнопка «Обновить» в UI всегда делает запрос вне очереди и сбрасывает счетчик повторов.

## 6. Визуальная индикация (Health Indicators)
*   **Good (< 150ms):** Зеленый пульсирующий индикатор, статус «Стабильно».
*   **Fair (150ms - 400ms):** Желтый индикатор, статус «Задержка».
*   **Poor (> 400ms):** Красный индикатор, статус «Медленно».

## 7. Этапы внедрения (Roadmap)
1.  ✅ **Этап 0:** Визуальные индикаторы на фронтенде (РЕАЛИЗОВАНО).
2.  **Этап 1:** Создание JSON-конфигурации и архитектуры на бэкенде.
3.  **Этап 2:** Реализация `BackgroundService` и логики «Окна тишины».
4.  **Этап 3:** Интеграция `ISmsService` и SMS-провайдера.
5.  **Этап 4:** Внедрение Retry Policy на стороне Angular-сервиса.
